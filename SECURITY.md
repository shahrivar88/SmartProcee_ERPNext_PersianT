# Security policy

## Supported versions

This is a small project. Security fixes are made only for the latest released version. Upgrade to the latest release before you report a problem, and make sure that the problem still occurs.

| Version | Supported |
| --- | --- |
| Latest 1.x release | Yes |
| Earlier releases | No |

## Report a vulnerability

Do not report a vulnerability in a public issue, pull request, or discussion. Do not disclose it publicly before it has been reviewed and a fix or a decision is available.

Report it privately:

1. On the GitHub page of this repository, open the **Security** tab and select **Report a vulnerability**, if private vulnerability reporting is available.
2. If that option is not available, contact the repository owner privately through their GitHub profile, and ask for a private channel. Do not include the vulnerability details in the first public message.

Include:

- the affected version, and the Frappe and ERPNext versions,
- the steps to reproduce the problem,
- the impact that you expect,
- a proposed fix, if you have one.

Do not include real customer data, passwords, or API keys in a report.

## What to expect

The maintainers will review each report in good faith. There is no guaranteed response time, and there is no guarantee that a fix will be made or released by a given date. When a fix is released, the changelog states it. Credit is given to the reporter if they want it.

## Scope

This policy covers the code in this repository. Report problems in Frappe Framework, ERPNext, or other apps to their own projects.
